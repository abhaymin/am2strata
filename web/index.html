Workshop

        
Make models in Rust on this PC: convert a Hugging Face model to GGUF, quantize it, merge a
          LoRA adapter (from Unsloth or PEFT) into its base. Jobs run one at a time and keep running if you leave this tab.
          

      

      

        
1 · Merge an adapter
          
A LoRA adapter folder (adapter_model.safetensors + adapter_config.json)
            into the Hugging Face model it was trained on. rsLoRA and MoE expert adapters are handled.

          
          
          
          
          
          
          
        

        
2 · Convert to GGUF
          
A Hugging Face model folder (safetensors, config.json, tokenizer) to one GGUF file, byte for
            byte as llama.cpp's converter writes it. Llama-family models for now.

          
          
          
          
          
          
          
          
          
        

        
3 · Quantize
          
A GGUF to a smaller type, matching llama-quantize --pure byte for byte.

          
          
          
          
          
          
          
        

        
4 · Make it a model am2Strata runs
          
Writes its run config and tokenizer folder, as a downloaded model gets, with the engine for
            its architecture (refused, with the reason, if no engine runs it). It then shows in the model list.

          
          
          
          
          
          
          
          
        

        
Train · coming next
          
LoRA training in Rust is built and tested on a small model; training real models (rotary
            attention, the full Llama forward) is being finished. Until then, train with Unsloth and merge here.

Cluster

          
Workers
            
A master is the am2Strata people and apps talk to; it keeps the keys, memory and queue. A
              worker is another am2Strata that runs models for it: set "cluster": {"role": "worker"} in its run
              config. Workers on this network show here as "wants to join"; type the 6-digit code the worker shows to pair it.
              Nothing joins by itself. A chat goes to a worker when only the worker has its model, or when this PC is busy and
              a worker has the same model loaded and idle; the answer comes back through here.

            

          
Add one in the run config
            
"cluster": {"workers": {
  "pc2": {"url": "http://192.168.8.50:8000", "key": "env:PC2_KEY"}
}}

            
Workers can also be listed in the run config (used from the next start); the key is then the
              worker's own API key (or env:NAME). Pairing in the app gives each master a key of its own instead, and the worker's
              main key never leaves it. A worker paired in the app is reached over TLS 1.3, each machine checking the other's
              certificate as it was paired (the worker's port "tls_port", default its API port + 443, must be reachable from
              the master). Workers listed in the run config are plain HTTP with the key: across a network you do not trust,
              connect those machines through your own VPN (Tailscale, WireGuard).

        


        

          
Clients

          
Client profiles
            
Each client (a laptop, an agent, a phone app) gets its own API key with its own tools and memory. An
              agent that sends only the address and the key gets these tools with no other setting. They are set in the run
              config, and used from its next start.

            

          
Add one in the run config
            
"clients": {
  "laptop": {"key": "a-long-random-key", "tools": ["memory", "web", "image", "speech", "mcp:*"], "memory": "laptop",
             "limits": {"media_jobs_per_hour": 20, "max_image_size": "1024x1024",
                        "max_video_seconds": 10, "web_queries_per_turn": 5}},
  "default": {"tools": ["web"]}
}

            
Tools: memory, web, image, video, speech, music, browser, code (run_python in the sandbox), and MCP
              servers by name (mcp:files) or every address server (mcp:*). "default" is what the main key gets.
